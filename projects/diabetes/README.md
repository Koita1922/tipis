# Классификация диабета по табличным данным

Учебный проект: CatBoostClassifier и локальное приложение Streamlit.
Признаки: пол, возраст, гипертония, заболевания сердца, история курения, ИМТ, HbA1c и глюкоза. Цель — бинарная метка `diabetes`.

## Запуск

Команды из корня репозитория, Python 3.10+:

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r projects/diabetes/requirements.txt
python -m streamlit run projects/diabetes/app.py
```

Модель включена в `models/`. Пути рассчитываются относительно файлов проекта, поэтому запуск не зависит от текущей папки.
В форме доступны все шесть категорий истории курения из исходных данных. Кодирование вынесено в общий модуль для обучения и интерфейса.

## Обучение и проверенный результат

```bash
python projects/diabetes/train.py
```

- Исходный CSV: 100 000 строк, 8 признаков и целевая метка.
- Удалены 3 854 полностью одинаковые строки **до** разделения.
- Стратифицированные train/validation/test: 57 687 / 19 229 / 19 230 строк; seed 42.
- CatBoost: 100 итераций, depth 6, learning_rate 0.1.
- Validation используется для выбора модели; итоговые метрики рассчитаны на отдельном test.

| Метрика | Значение на test |
|---|---:|
| ROC AUC | 0,9782 |
| Accuracy | 0,9700 |
| Precision положительного класса | 0,9819 |
| Recall положительного класса | 0,6730 |
| F1 положительного класса | 0,7986 |

Порог классификации — 0,5. [Полные результаты и матрица ошибок](reports/metrics.json).
Высокая accuracy не означает, что модель находит все положительные случаи: recall составляет около 67%. Это один воспроизводимый holdout-эксперимент, не кросс-валидация и не клиническая оценка. Калибровка вероятностей не проводилась.

## История проекта

[Исходный ноутбук](notebooks/original_experiment.ipynb) сохраняет первоначальные расчёты, ROC-кривую, матрицу ошибок и важности признаков. Исторический ROC AUC — 0,9795, F1 — 0,81, recall — 0,69. В нём использовалось разделение 80/20 без удаления дублей, а test передавался как eval_set. Поэтому исторические и новые результаты не следует смешивать.

При подготовке портфолио с помощью ИИ исправлены:
- несовпадение кодирования истории курения между обучением и интерфейсом;
- пути, привязанные к рабочей папке и Windows;
- отсутствие отдельных validation/test и очистки дублей;
- структура, документация и проверки.

Для исторического ноутбука нужны дополнительные зависимости:

```bash
python -m pip install -r projects/diabetes/requirements-notebooks.txt
```

Запускайте Jupyter из `projects/diabetes/notebooks`. При запуске ноутбук сохраняет `models/original_model.cbm`, не заменяя модель исправленного эксперимента.

## Тестирование

```bash
python -m pip install pytest
python -m pytest projects/diabetes/tests -q
```

Тесты проверяют совместимость с исходным кодированием, порядок признаков, отсутствие изменения входных данных и обработку неизвестной категории. Интерфейс дополнительно проверен через Streamlit AppTest: загрузка модели и нажатие кнопки расчёта.

## Данные и ограничения

Файл `data/diabetes_prediction_dataset.csv` присутствовал в исходном репозитории. Первоначально ссылка на источник и лицензия не были записаны; их нужно восстановить перед дальнейшим распространением. Статистика датасета не доказывает его клиническую достоверность.

Приложение предназначено для демонстрации ML и не используется для медицинской диагностики. Коммерческого внедрения нет.
